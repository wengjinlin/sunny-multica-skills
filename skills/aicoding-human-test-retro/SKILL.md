# aicoding-human-test-retro：人工测试报告复盘归因

**定位**：人工测试验证报告（`docs/human-test-reports/`）的复盘归因器。报告由人类维护、agent 只读——本 skill 只消费报告；「测试者只写现象、归因不下放」的约定不变，归因分析与经验沉淀由本 skill 承担，复盘完成后将已读报告归档。

**执行者**：DocKeeper agent（周级 autopilot 触发为主，人工触发为辅）。
**分析对象**：主目录下未归档的全部报告（见第 2 步扫描规则）；⚠️ 的逐问题归因，✅ 全过的只计数登记。

## 执行流程

### 第 0 步：前置

1. `multica repo checkout <REPO_URL>`（或确认仓库已在本工作区），`git fetch origin`
2. MR 目标分支与保护分支清单以仓库 `AGENTS.md` §4 为准

### 第 1 步：停等检查

- 存在未合并的 `retro-*` 分支 / MR → 本期**不建新 MR、不移动任何报告**，未读报告留在主目录并入一条提醒（autopilot 场景输出在 run 结论；人工场景直接告知），等上期 MR 人工合并后下期自然收口——人不决策链路就停在提醒上，不丢不重
- `archive/` 目录不存在 = 首期（主目录全部报告即本期范围，天然全量，无需特殊处理）

### 第 2 步：扫描未读报告

- `docs/human-test-reports/` **主目录**下的 `*.md`，排除 `_template.md`、`index.md`（兼容存量仓库旧结构，新仓库无此文件不影响）、`archive/` 子目录——剩余即**未读集合**
- 未读集合为空 → 直接进第 7 步收工

### 第 3 步：逐问题归因（仅 ⚠️ 报告的问题行）

对每个问题行交叉取证，给出「责任环节 + 证据 + 置信度（高/中/证据不足）」。

**责任环节枚举**（权威源在本 skill，index.md 引用不自存）：PM澄清 / specs / design / tasks拆分 / Developer实现 / Reviewer漏审 / Tester漏测 / 环境 / 需求理解偏差

**证据链四源**：

| 源 | 取什么 | 佐证什么 |
|---|---|---|
| 报告问题行 | 现象/处理/修改文件三列 | 出了什么、人在哪修的 |
| 该 MR 的 diff | 修改文件的实际改动 | 修复形态（补配置？改业务逻辑？改接口契约？） |
| 对应 change 的 OpenSpec 工件 | proposal / specs / design / tasks | 该说清而没说清的（缺字段/含糊） |
| issue 上 Tester 的 test-report | 已测项清单 | 该测到而没测到的 |

- 「对应需求」字段缺失、change 已归档或证据拿不全 → 标「证据不足」，只按现象粗归类并注明，**不猜**
- 同形态问题跨需求重复出现 → 底层缺陷信号（进第 4 步分拣）

### 第 4 步：分拣产物（判据一句话：「这个坑换个项目还会踩吗？」）

| 类别 | 判定 | 产物 |
|---|---|---|
| 项目级的坑 | 只在本项目成立（业务规则反直觉、表结构约定、模块代码习惯、**稳定存在须绕开的**环境特性），换项目不会复发 | lesson 草案：按 lessons index 规定格式（日期 / change-id / ❌✅ 对照）追加到 `docs/lessons/{Role}.md` |
| 底层能力缺陷 | 工件模板缺字段、agent 指令没约束到、审查关卡漏项——任何项目都会复发 | **根治点定位清单**：缺陷描述 → 权威源文件位置（如 `aicoding-agent-bootstrap/agents/PM.md` 建单模板节）——只列不动手，由人拿到优化工作区决策 |
| 环境类 | 当次环境故障 / 配置错误，修复即消失（稳定特性须绕开的归上一行） | 只进期报计数，供人做环境治理 |

### 第 5 步：聚合

- 按责任环节计数；同类 ≥3（阈值沿用 index 原值）列高频讨论项
- 同类项目级坑**第 2 次**出现 → 标「建议晋升宪法」（人确认后写入 CLAUDE.md / REVIEW.md 红线并给原条目标「已晋升」——晋升动作由人触发，本 skill 只标记）

### 第 6 步：产出 MR（期报 + 归档一揽子）

1. 建 `retro/{yyyymmdd}` 分支（基于 `origin/master`）
2. 写期报 `docs/human-test-reports/retro/{YYYY-MM-DD}.md`：本期覆盖报告清单（附归档后相对路径，可跳转）/ 逐问题归因表 / 环节聚合计数 / 高频项 / 晋升候选 / 根治点定位清单
3. lesson 草案追加到 `docs/lessons/{Role}.md`
4. **归档**：`docs/human-test-reports/archive/{期报日期}/` 二级目录（无则新建，名字与期报文件名对应；同日第二期加序号 `-2`），`git mv` 本期全部已读报告移入——**目录结构即游标**：主目录剩余的 md 就是下期未读
5. `git push` 后 GitLab API 建 MR：JSON body 写文件传参（form 编码中文会 500）；`PRIVATE-TOKEN: $GITLAB_TOKEN`；API base 与 project-id 从项目上下文获取，不写死；**MR 描述 = 期报全文**——人就在 MR 页面完成决策（期报 / lesson 草案 / 归档移动，删改均在此 MR 内完成）
6. 人工触发场景在 chat 内回报 MR 链接与要点

### 第 7 步：无新报告收工

- 主目录无可读报告且无未合并停等项：autopilot 场景静默结束；人工触发场景回复「主目录无未读报告」

## 读写分区

- **只读**：报告内容（`日期-分支名.md` 与测试人写的任何内容，**字节不动**；复盘仅做整体归档移动 `git mv`，移动本身随 MR 人审生效）
- **写区**（仅三处，且全部经 MR 人审生效）：`retro/` 期报、`docs/lessons/` 条目追加、`archive/` 归档移动

## 铁律

- 报告内容永不修改——复盘只整体归档，不篡改证据
- 只改 `docs/`，禁碰任何代码
- MR 由人合并，禁直推保护分支
- 存疑归因一律标「证据不足」，不猜
- 根治点定位清单只列不动手——bootstrap 源与 agent 运行态属工作区配置层，治理归优化工作区
- `$GITLAB_TOKEN` 禁止打印、写入文件/评论/commit；变量为空则报告 env 未配置，不硬编绕路

## 维护约定

- 责任环节枚举权威源在本 skill
- 期报格式以 `retro/` 首篇建立后沿用，结构变更回写本 skill
