# 人工测试验证报告（human-test-reports）

## 机制

- agent 流（五阶段链）完成、DevOps 建 MR 后，由**人**拉取 `feature/{change-id}` 分支做本地集成测试验证；有问题人自行修改收口，**不再打回 agent 流重跑**（加速交付）
- 报告填写者是**测试人员，不要求了解本流程**：只写清「问题现象 + 处理方式 + 修改文件」，全部通过也要写
- 报告命名 `日期-分支名.md`，commit 进当前 feature 分支，随 MR 入库
- **归因与分析在复盘阶段做**（见下方复盘操作），不下放给测试者
- 本目录的报告由人类维护，agent 只读

## 复盘操作（人工发起，流程人员进行）

1. 通读自上次复盘以来的全部报告；对每个 ⚠️ 问题，由**流程人员**判定责任环节并补填索引表该列——归类枚举：PM澄清 / specs / design / tasks拆分 / Developer实现 / Reviewer漏审 / Tester漏测 / 环境 / 需求理解偏差
2. 按责任环节聚合计数；高频环节（建议阈值：同类 ≥3 次）逐类讨论：是需求澄清不足、工件模板缺陷、agent 指令缺陷还是审查关卡漏项
3. 产出：lesson 条目（写进 `docs/lessons/` 对应角色文件，格式见其 index）或模板/指令修订（走对应 bootstrap skill 源）
4. 更新本表「复盘状态」列（已提炼 / 无需提炼）
